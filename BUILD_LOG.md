# Fix same-origin registration check behind local host normalization (2026-10-27)

- **Files changed:** `app/api/[...path]/route.ts`, `BUILD_LOG.md`.
- **Diagnosis and change:** A registration POST was blocked at the Next proxy because it compared `Origin` only to `request.nextUrl.origin`. When Next dev is bound on `127.0.0.1`, normalized request origin can differ from the browser's same-origin host. Added an origin parser that first accepts Next's normalized origin, then compares against the externally received `Host` and trusted forwarded host/protocol headers. Mutations with mismatched authority/scheme or cross-site `Sec-Fetch-Site` remain rejected; no allow-all or CSRF bypass was added.
- **Validation (actual):** Final `make quality` PASS (Ruff; ESLint; TypeScript; 41 Python tests; dataset audit; Python compilation; Next.js production build). Live POST through `localhost:3000` with CSRF cookie/header and matching localhost Origin passed the proxy and returned FastAPI's expected HTTP 403 invite-only response. A mismatched HTTPS hostile origin remained blocked by the proxy with the cross-origin HTTP 403. Matching loopback host smoke also reached FastAPI. `/register` returns HTTP 200.
- **Security boundary / limitation:** Comparison uses the incoming `Host` header and Next's normalized request URL; forwarded headers are deliberately not trusted as origin authority. Browser end-to-end testing was not run.
